## What this repo is
A standalone **watchOS 10+** app that generates **3x3 and Square-1** scrambles and shows the resulting puzzle state as a map (3x3 net, or a WCA-style Square-1 top/bottom diagram). Runs independently of any iPhone companion (`WKRunsIndependentlyOfCompanionApp = YES`).

## Layout
- `RubiksScramble/` — Xcode project + Watch App target.
  - `RubiksScramble Watch App/CubeState.swift` — 54-facelet engine. **Do not change the U,D,F,B,L,R face ordering or the perm tables** without re-running `scripts/verify_cube.py`; they're geometrically generated and verified.
  - `RubiksScramble Watch App/ScrambleGenerator.swift` — WCA-notation 3x3 scramble generation (never repeats the same face on consecutive moves), plus the `Puzzle` enum (3x3 / Square-1) that maps each puzzle to its generator, length range and label.
  - `RubiksScramble Watch App/Square1Scrambler.swift` — random-move Square-1 scrambles, `(x,y)/` tokens, x/y in −5…6. Tracks layer shape so every turn leaves both layers sliceable. Model and sign convention follow csTimer's random-move generator; from solved, `(1,0)` and `(0,-1)` are legal but `(-1,0)` / `(0,1)` are not — any change must keep that. Re-run `scripts/verify_square1.py` after touching it (mirrors the Swift and replays every scramble on an independent boundary model).
  - `RubiksScramble Watch App/ContentView.swift` — main UI. Root is a horizontal `.page` TabView: swipe left/right between the 3x3 and Square-1 pages (selection persisted via `@AppStorage("puzzle")`; no switcher buttons — the page title, `Puzzle.name`, says which puzzle you're on). Each puzzle keeps its own scramble (`moves: [Puzzle: [String]]`) and length. Each puzzle page nests a `.verticalPage` TabView: scramble, then swipe down for its map (`CubeMapView` for 3x3, `Square1MapView` for Square-1).
  - `RubiksScramble Watch App/Square1MapView.swift` — `Square1State` (piece-level state in TNoodle's exact cell model: same turn/slice code, plus the middle-layer flip) and a Canvas port of TNoodle's `drawScramble`, so the map matches WCA scramble-sheet images: top face, middle-layer bar (one bar when solved, split red/orange when flipped), bottom face. Uses the WCA Square-1 colour scheme — **yellow top, red front** (L blue, B orange, R green, D white) — which differs from the 3x3 net's white-top/green-front.
  - `RubiksScramble Watch App/TimerView.swift` — the **Timer card** (4th card; not a `Puzzle` case, the complication reaches it via `ComplicationTarget.timer`, `scramblegen://timer`). Crown sets a 0-30 s inspection countdown (`@AppStorage("timerCountdown")`, default 15; haptic ticks at 8/3/2/1 s, strong notification at 0), then a Date-based count-up in large monospaced digits. **Stop by motion:** `StopDetector` runs CMMotionManager device motion at 50 Hz; a `userAcceleration` magnitude spike >= **`TimerCard.stopSpikeThreshold`** (2.0 g; THE constant to tune) followed by 0.5 s below `stillThreshold` stops the timer at the *spike's* time. Motion is ignored for the first 1.0 s (`startLockout`); tapping the screen also stops. Result view: time, session best, Again, last 5, Reset. `RuntimeKeeper` runs a `WKExtendedRuntimeSession` (Info.plist `WKBackgroundModes` = `self-care`, in `BuildInfo.plist`; no entitlement/profile change) so it survives wrist-down; without a running session, backgrounding aborts the run. Leaving the card stops the timer, motion and session.
  - `CustomizationView.swift` — **Customization** card (gearshape, teal `CustomizationCard`, between Ao5 and About; `showCustom` in ContentView) opening `CustomizationScreen`, a `Form` with one `Section` per feature. Settings persist in UserDefaults via `@AppStorage` keys defined in `Ao5Settings` (`ao5.feedback` default on, `ao5.feedbackInterval` default 10 ms from 1/5/10/25/50/100/500 (picker hidden when feedback is off), `ao5.crownStep` "Crown speed" 1/2/5/10 ms per detent default 1, `ao5.speedUp` fast-spin acceleration default on). The card shows only adjustable controls: no captions/footers/explanatory rows. To add a feature: add its keys/defaults + a new `Section`.
  - `AverageOfFive.swift` + `Ao5View.swift` — **Ao5 calculator** (feature/ao5-entry; not in the submitted 1.0 build). Its own top-level card (`Ao5Card`, purple, `5.square` icon; Digital Crown dials the time: crown value = ms (`digitalCrownRotation by: 1`, `.medium`), `Ao5Dial.addCrown` = units x ms-per-unit; with acceleration on the step is a velocity tier from smoothed units/s (<25 -> 1 ms, <60 -> 10, <130 -> 100, else 1000; never below the Crown speed setting; a pause > 0.3 s resets to slow), tune in `Ao5Dial.step(forSpeed:)`; the crown binding recentres itself when far from the middle and ignores its own echo event; `resetMotion()` plus a settings reload on appear/select/Set/New; re-tapping the selected empty slot keeps the dialled time; 3 decimals, one click haptic per `interval` ms boundary crossed (integer compare, max 1 per 30 ms, built-in crown haptics off); compact one-row average/best header, no title; tap a slot to select, Set stores it, live best/average; between Timer and Customization in `CardStack`) opens `Ao5Screen` directly (wrapped in a `NavigationStack` in `ContentView.openContent`; not reachable from the Timer card any more): +2/DNF toggles per solve, then the WCA Ao5 (drop fastest and slowest, DNF = slowest, 2+ DNFs = DNF, dropped times in parentheses, best single). The maths lives in `AverageOfFive` (pure Foundation, integer milliseconds; times shown with 3 decimals; the average is the middle three summed / 3 rounded to the nearest ms, not centisecond-rounded). Tests: `cd Tests/Ao5 && swift test` on a Mac (the package symlinks the shipping source file); `python3 -I scripts/verify_ao5.py` runs anywhere. The new files are registered in the watch target of `project.pbxproj`; there is no XCTest target in the Xcode project.
- `RubiksScramble/ScrambleWidget/` — watch-face complication (WidgetKit extension `ScrambleWidgetExtension`, bundle `com.pcintaiwan.scramblegen.watch.widget`, watchOS 10, embedded in the watch app). `AppIntentConfiguration` with a `Puzzle` AppEnum parameter (options = `Puzzle.allCases`); `widgetURL` `scramblegen://puzzle/<3x3|square1>` handled by `.onOpenURL` in `ContentView`. Compiles the app's `ScrambleGenerator.swift`, `CubeState.swift`, `Square1Scrambler.swift` and `PuzzleStyle.swift` (colours, symbols, deep-link parsing), so keep those free of watch-app-only types. Details, the Apple-side checklist and signing: `docs/WATCH_COMPLICATION.md`.
- `mockup/` — HTML/CSS mockup of the watch screens; `node mockup/shot.mjs` rerenders the PNG previews (uses Playwright + Chromium at `/opt/pw-browsers`).
- `scripts/verify_cube.py` — regenerates and validates the cube turn tables.
- `scripts/verify_square1.py` — validates the Square-1 scrambler.

## Design conventions
- Cube colours (also in `CubeState.swift` `stickerColor`):
  - U white, D `#FFD500`, F `#30D158`, B `#0051BA`, L `#FF5800`, R `#CE2029` (fire-truck red).
- `AccentColor` = cube green `#30D158`, so the New Scramble button matches the orientation pill.
- Orientation pill text: **"White top · Green front"** (standard WCA scrambling orientation) for 3x3; for Square-1 it reads **"(top, bottom) · / = slice"** as a notation key.
- Scramble formatting: every move padded to its puzzle's widest token, single-space joiner, explicit `\n` rows — 3x3: 2-char columns, 5 per row, 19pt; Square-1: each number right-aligned in a 2-char column (`( 1, 0)/`, display only — stored moves stay unpadded), 8-char tokens, 2 per row, 16pt. Rows are left-aligned for both puzzles, so a short last row sits under the first column. Keeps row width fixed across watch sizes.
- Length per puzzle: 3x3 counts face turns (default 20, 1–50, label "Length"); Square-1 counts slices (default 15, 1–30, label "Slices").

## watchOS focus gotcha (already burned us once)
The length pill captures the Digital Crown via `@FocusState`. Use `@FocusState<EnumField?>`, not `@FocusState<Bool>`: setting Bool `false` lets SwiftUI auto-restore focus to the only focusable view on the page, so dismiss gestures look like re-activations. Setting an enum `FocusState` to `nil` actually releases focus. Never make the pill a `Button`: a Button tap moves focus to itself before its action runs, which races any focus toggle.

Current model (`ContentView.swift`): `@State isSelected` is the single source of truth for "pill selected" and drives the visuals; focus only routes the crown. The pill is `.focusable(isSelected)`, and an `onChange(of: isSelected)` hands focus over one tick later; losing focus externally deselects.
- Tap length pill → toggles `isSelected` (select: crown adjusts length; deselect: crown scrolls the page).
- Tap scramble notation → deselect.
- Tap New Scramble → deselect + regenerate.
- Page disappears (swipe to the other puzzle) → deselect.

Earlier toggle attempts failed on-device (Button focus race, then Bool auto-restore), which is why the pill was one-directional for a while. If the toggle misbehaves on a real watch, the known-good fallback is select-only on the pill, with deselect via the notation tap.

## Distribution (TestFlight via CI, ported from xerothermic/GoWatch)
- **Ships as "Watch Scramble"** (display name; the Xcode scheme/target are still `CubeScramble`) — "Rubik's" is a live trademark, so display names and the App Store Connect record avoid it.
- App Store releases: `.github/workflows/release.yml` (manual dispatch, `dry_run` defaults to true, or a `v*` tag — `testflight.yml` deliberately ignores tags). It uploads a candidate; choosing the build and submitting for review is done by hand in App Store Connect (`docs/TESTFLIGHT.md`, "App Store release").
- **Build numbers:** sequential, from `ci/build-number` (one integer; missing = 0). Both workflows call `ci/reserve-build-number.sh`, which adds 1, commits it back with `[skip ci]` (GITHUB_TOKEN pushes never trigger workflows) to the branch being built (main for tags), and uses it as `CURRENT_PROJECT_VERSION`. Both share the `build-number` concurrency group, so no races; pushes are fast-forward only with retry. dry_run reads without bumping; the `build_number` input overrides. **Reset `ci/build-number` to 0 when `MARKETING_VERSION` changes** (Apple only needs a rise within one version string). Version 1.0 used epoch-minute numbers (latest 29891499), so a 1.0 hotfix must pass `build_number` above that by hand. main has no branch protection; if it gains some, allow github-actions[bot] to push or the bump fails.
- **Watch-only (no iPhone app)**: the watch target sets `WKWatchOnly = YES` and has no `WKCompanionAppBundleIdentifier`. Xcode has no App Store distribution method for a bare watchOS archive, so the `CubeScramble` target is a code-less **watch-only container** (`productType = com.apple.product-type.application.watchapp2-container`, iOS SDK, no sources, no icon) that embeds the watch app under `Watch/` — the same shape Xcode's "Watch App" template generates. Watch target keeps `SKIP_INSTALL = YES` (correct ONLY because it's embedded in the container). No iPhone UI exists, so App Store Connect needs Apple Watch screenshots only (avoids the 4.2 thin-iPhone-app risk).
- Bundle IDs: container `com.pcintaiwan.scramblegen` (parent — this is what the ASC app record binds to; the record's platform is iOS, Apple has no watchOS record type), watch `com.pcintaiwan.scramblegen.watch`.
- Privacy manifest: `RubiksScramble Watch App/PrivacyInfo.xcprivacy` declares UserDefaults reason `CA92.1` for `@AppStorage("puzzle")`. Update it if new required-reason APIs are used.
- CI: `.github/workflows/testflight.yml` (repo-agnostic; per-repo values in `ci/release.config`). Archives shared scheme `CubeScramble` (the container; the scheme runs the watch app) for `PLATFORM=watchOS` (the watch-only scheme only offers watchOS destinations) on a `macos-26` runner and uploads to App Store Connect.
- **Eight** GitHub Actions secrets required (seven listed here, plus `PROVISIONING_PROFILE_WATCH_WIDGET_BASE64` below): `APPLE_TEAM_ID`, `APPLE_DIST_CERT_P12`, `APPLE_DIST_CERT_PASSWORD`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_PRIVATE_KEY`, plus `APPLE_PROVISIONING_PROFILES` (base64 tar.gz of the App Store `.mobileprovision` files — per-app, this repo needs its OWN profiles, named exactly "ScrambleGen App Store" / "ScrambleGen Watch App Store" to match `PROVISIONING_PROFILES` in the config). Signing is manual for archive and export (Apple Distribution cert + those App Store profiles, no `-allowProvisioningUpdates` at archive), so CI never needs or creates a development certificate; the workflow fails fast if a secret or profile is missing or doesn't match.
- **Complication extension signing:** a third bundle, `com.pcintaiwan.scramblegen.watch.widget`, profile "ScrambleGen Watch Widget App Store" in `PROVISIONING_PROFILES`, delivered by an **eighth** secret `PROVISIONING_PROFILE_WATCH_WIDGET_BASE64` (base64 of that single `.mobileprovision`; both workflows require and install it). Until Patrick registers the App ID, creates the profile and adds the secret (`docs/WATCH_COMPLICATION.md`), every TestFlight/release run fails at the secrets check, so pushes to `bob/watch-complication` use `[skip ci]`. The extension must keep the same `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` as the watch app (CI overrides both for all targets; keep the project defaults in sync when bumping by hand). `.github/workflows/compile-check.yml` (manual) does an unsigned watchOS Simulator build and checks the embedded extension's versions.
- Named profiles + `Apple Distribution` cert are deliberate: cloud signing fails with a Developer-role ASC key ("Cloud signing permission error").
- App icons: 1024 RGB (no alpha) PNG in the watch target's `AppIcon.appiconset` (the watch-only container has no icon) — an empty icon set passes the build and fails Apple validation ~20 min later.
